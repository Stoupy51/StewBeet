      dicts#

      super_merge_dict(
      dict1: JsonDict,
      dict2: JsonDict,
      ) → JsonDict[source]#

      Merge two dictionaries recursively without modifying them, dict2 winning and lists merged without duplicates.

      >>> super_merge_dict({"a": 1}, {"b": 2})
{'a': 1, 'b': 2}
>>> super_merge_dict({"a": 1}, {"a": 99})
{'a': 99}
>>> super_merge_dict({"nested": {"x": 1, "y": 2}}, {"nested": {"y": 99, "z": 3}})
{'nested': {'x': 1, 'y': 99, 'z': 3}}
>>> super_merge_dict({"tags": ["a", "b"]}, {"tags": ["b", "c"]})
{'tags': ['a', 'b', 'c']}
>>> result = super_merge_dict({"items": [{"id": 1}]}, {"items": [{"id": 2}]})
>>> result["items"]
[{'id': 1}, {'id': 2}]

      model_cache#

      MODEL_CACHE_NAME: str = 'stewbeet_model_encoder'[source]#

      Name of the beet cache holding serialized models.

      MODEL_CACHE_MAX_AGE: timedelta = datetime.timedelta(days=7)[source]#

      Entries untouched for longer than this are dropped at the start of a build.

      MODEL_CACHE_MIN_SIZE: int = 8192[source]#

      Contents whose marshalled size is below this are serialized directly instead of cached.

      Caching costs a directory lookup, a file read and a timestamp update, which together run to roughly 0.2ms per entry; serializing runs at roughly 55ms per megabyte. Below a few kilobytes the cache is therefore slower than simply doing the work, and on a pack with thousands of tiny json files that overhead adds up to more than it saves.

      EXACT_JSON_TYPES: frozenset[type] = frozenset({<class 'NoneType'>, <class 'bool'>, <class 'float'>, <class 'int'>, <class 'str'>})[source]#

      Types marshal accepts as-is, checked by identity since it rejects every subclass.

      to_plain_builtin(value: Any) → Any[source]#

      Rebuild a value out of dict, list, str, int, float, bool and None so marshal serializes it.

      marshal rejects subclasses: a single Resource, a str but not exactly one, would make its model uncacheable. Values with the same plain form serialize to the same json text, so normalizing is safe, tuples becoming lists. marshal back-references repeated objects, so the key also depends on which values are the same object. Anything else is returned untouched, letting marshal reject it.

      >>> to_plain_builtin({"a": (1, 2), "b": [None, True]})
{'a': [1, 2], 'b': [None, True]}
>>> class MyStr(str): pass
>>> plain = to_plain_builtin({"model": MyStr("ns:item/x")})
>>> plain, type(plain["model"]) is str
({'model': 'ns:item/x'}, True)
      class ModelSerializationCache(directory: Path)[source]#

      Bases: object

      Content-addressed, cross-build cache of serialized models.

      Serializing models dominates build time on packs that generate many variants of the same geometry: the elements array is by far the biggest part of a model file, and packs with camouflages / powered states / zoom levels emit the same geometry hundreds of times.

      Entries are keyed on a hash of the model content itself, not on where it came from. That is what makes the cache safe to keep between builds: any change that alters a generated model: editing the source geometry, changing how models are built, upgrading StewBeet: changes the hash and misses the cache. There is no invalidation rule to keep in sync, and no way to serve a model that was generated by code that no longer exists.

      The hash covers the encoder settings and the versions of everything involved in producing the text (Python, marshal, stouputils), since those decide the formatting rather than the content. marshal is used to turn the model into bytes because it is a C serializer for exactly these primitive types and runs several times faster than json.dumps; its output is stable within a given interpreter version, which is why that version is part of the key.
