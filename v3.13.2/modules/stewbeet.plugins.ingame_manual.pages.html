      📄 pages#

      Page classes for the in-game manual.

      base#

      The Page base class and lifecycle.

      A page is a self-contained unit that knows how to render itself directly to a dialog body: a list of Minecraft text components where element 0 is the parent whose style (notably its font) cascades to the siblings. Subclasses implement build(); the base render() wraps it and applies developer transformers last, so per-item/page overrides compose cleanly.

      *,
      anchor: str,
      title: str = '',

>>> page.render(None)  # the default build() yields [], then transformers run in order
['!']

      Stable identity used for ordering and deferred links (e.g. “intro”, “category:Materials”, “item:wrench”). Must be unique within a manual.

      title: str[source]#

      Human-readable page title.

      item_id: str | None[source]#

      If this page represents an item, its id (drives PageRef(item=...) resolution and dialog atlas sprites).

      button_layout: ButtonLayout | None[source]#

      Per-page override of the manual-wide button layout.

      book_texture: str | Image.Image | None[source]#

      Per-page override of the book background (“book.png”). A path (project path, or a filename resolved against the templates dir so manual_overrides files work) or a ready PIL image. None = shared book.

      book_font: str[source]#

      Glyph char registered for book_texture (set during emit, “” = shared BOOK_FONT).

      home_texture: str | Image.Image | None[source]#

      Per-page override of the home button (“home.png”), same accepted values as book_texture. Keep the default’s 16x16 proportions so the navigation row stays aligned. None = shared home.

      home_font: str[source]#

      Glyph char registered for home_texture (set during emit, “” = shared HOME_FONT).

      home_button: bool[source]#

      Whether this page shows the home button in its navigation row (an invisible spacer keeps the prev/next layout when hidden). The first page never shows it regardless of this flag.

      transformers: list[Transformer][source]#

      Developer hooks applied to the rendered content, in order.

      optimize: bool[source]#

      Whether the optimizer may merge this page’s components. Set False for pre-built content whose element positions are significant (e.g. a RawPage relying on absolute indices).

      prepare(manual: Manual) → None[source]#

      Heavy, order-independent setup (collect data, allocate glyphs). Default: no-op.

      build(manual: Manual) → list[TextComponent][source]#

      Produce the raw page content. Subclasses override this.

      render(manual: Manual) → list[TextComponent][source]#

      Build the page then apply transformers (last), returning final content.

      resolve_button_layout(manual: Manual) → ButtonLayout[source]#

      Return this page’s effective button layout (own override or manual default).

      texture_page#

      A page whose body is a custom background texture, optionally with text baked into it.

      This is the feature that lets developers ship “different textures for different pages and the text/descriptions on the texture itself”: supply a background image (path or PIL image) and a list of BakedText drawn onto it via PIL. The composited image is registered as a single full-page glyph; optional Minecraft body components can be added underneath (e.g. clickable links).
